How the model works

The simulation advances in 10s ticks. The rules follow Karpenter v1. Where the real controller is more complex, the model is simpler, so use it to build intuition, not to predict exact numbers.

  • Requests, not usage. Consolidation packs by pod resource requests. Actual CPU usage is never considered, just like the real controller.
  • Order of methods: Emptiness, then multi-node consolidation (binary search over up to 100 candidates, replacing them with at most one cheaper node), then single-node (delete, or replace with a cheaper node). One command is computed at a time, re-validated after 15s, then executed.
  • Candidates must be Ready and have had no pod added or removed for consolidateAfter. Nodes are excluded if they run a karpenter.sh/do-not-disrupt pod or a pod whose PDB currently allows 0 disruptions.
  • Budgets: the most restrictive active budget for the reason wins. Percentages are rounded up against the NodePool's node count, and nodes already disrupting count against the budget. Schedules are daily windows, like 0 9 * * * with a duration. If no budget matches a reason, it's unlimited.
  • Replacements are launched first. Candidates are tainted immediately and drained once the replacement is Ready. Evictions respect PDBs, and evicted pods are recreated by their controller.
  • Provisioning: pods are bin-packed while any allowed instance type still fits, then the cheapest fitting on-demand type is launched. Nodes take 60s to become Ready.
  • kube-scheduler places pods on Ready nodes with NodeResourcesFit scoring, either LeastAllocated (the default, which spreads pods) or MostAllocated (which packs them).
  • Instance types: c5/m5/r5, large to 8xlarge, at approximate us-east-1 on-demand prices. Allocatable subtracts EKS kube-reserved, the eviction threshold, 7.5% VM memory overhead, ENI max-pods and DaemonSet overhead.
  • Not modelled: spot and spot-to-spot, drift and expiration, affinity and topology spread, NodePool limits, pod priority, terminationGracePeriod, and multiple NodePools.
